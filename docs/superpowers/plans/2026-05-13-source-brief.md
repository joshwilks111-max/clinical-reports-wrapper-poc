## Goal

A standalone, runnable proof-of-concept that lands a single architectural thesis in **<5 minutes from cold clone**:

> **Block-per-block routing.** A clinical report is a sequence of blocks. Each block has a type. The agent routes each block to the correct deterministic formatter — it does not generate format output itself. Formatting is a tool the agent calls, not something the agent does.

A founder clones the repo, runs one command, sees the report generate block by block, opens the audit JSON, and goes: *"oh — this guy knows how Heidi Reports should actually be built."*

## Architectural Thesis (state this clearly in README)

- The agent's job is **routing decisions**, not output generation.
- Each `TemplateBlock` is a **tagged union**: `verbatim | structured | generative`.
- The agent reads the block type → calls the matching formatter → never invents format.
- This is the same split as Claude Code skills calling deterministic tool code: skills run code, agents don't re-derive code logic per call.
- **Win**: predictable output shape, smaller LLM token cost, deterministic verbatim and structured sections, generative reserved for where it earns its cost.

## Scope — what's IN

- **Transcript-shaped canned input** — one JSON file representing a clinical transcript. Realistic enough to be plausibly Heidi-shaped. **No real patient data.**
- **Three TemplateBlock types**, one example of each:
  - `verbatim` — fixed text the report always contains (e.g., "This report has been generated under the requirements of ACC Section 32 IOA assessment standards."). **No LLM call.**
  - `structured` — fields extracted from transcript and rendered into a known schema (e.g., functional status grid: walk distance, pain VAS, ROM measurement). LLM call returns JSON; deterministic formatter renders the table.
  - `generative` — free-text clinical impression / synthesis paragraph, LLM generates with prompt guard rails.
- **Audit hook** — fires on every LLM call (structured + generative blocks). Dumps to `audit/<timestamp>-<block-id>.json`: prompt, response, block context, model used, tokens. Human-readable, pretty-printed.
- **Canned LLM responses** — recorded JSON fixtures replay deterministically. No API key, no network call required for `make demo` to work. Live mode behind a `--live` flag (stretch goal, can defer).
- **Single command** — `make demo` (or `bun run demo`, depending on stack choice). Cold-clone → command → output in <60 seconds. **No env vars required.**
- **Heavy test coverage** — 90% target. Tests cover each block type, the router, the audit hook, the canned-response replay, and the end-to-end demo path. CI on push, must be green to merge.

## Scope — what's explicitly OUT

- No json-rules-engine layer.
- No multiple templates — one example template only.
- No real Heidi transcript-format integration.
- No live API mode in v1 (stretch goal behind a flag, fine to defer).
- No UI. Console output + JSON files only.
- No multi-clinician, no auth, no persistence beyond the audit JSONs.
- No "production-readiness" theatre (no Dockerfile, no Terraform). It's a PoC.

## Decision Log

- **Canned responses, not live API.** Founders-test demands a zero-friction demo: clone → command → output, no setup. Canned is **also a credibility signal** — Josh demonstrates he knows how to constrain scope in a proof-of-concept. The audit hook still dumps real-shaped JSON; the architecture is fully visible. "They don't need to poke it and squeeze it, even though I can make it squishy."
- **Three block types, not two.** Two would let a reader say "that's just an if/else." Three makes the tagged-union architecture obvious without extrapolation. The structured/generative split is where the thesis lives.
- **New repo, fresh start.** Existing local codebase isn't aligned with this scope; reshaping is more expensive than scaffolding clean.
- **Heavy test coverage is non-negotiable.** Same calibration logic as the skills repo: Heidi bar is high, test discipline is the credibility signal.
- **Final repo name TBD** — candidates: `clinical-reports-wrapper-poc`, `block-routing-poc`, `template-block-poc`. Pick at execution time; flag if unsure.

## Test plan (heavy coverage, ~90% target)

- **Unit tests**:
  - `verbatim` formatter: returns expected fixed string. No LLM call made.
  - `structured` formatter: given a stub LLM response (JSON), renders correct table shape.
  - `generative` formatter: given a stub LLM response (string), wraps/cleans correctly.
- **Integration tests**:
  - Router: given a `TemplateBlock[]`, asserts correct formatters called in order with correct inputs.
  - Audit hook: assert one JSON file per LLM call, correct shape, includes prompt + response + block context + model + tokens.
- **Replay determinism**:
  - Run `make demo` twice → identical output, identical audit JSONs (modulo timestamps).
- **End-to-end**:
  - `make demo` exits 0, produces expected console output, audit dir has expected file count.

**Coverage gate**: CI fails below 90% line coverage on `src/`.

### Stdout format spec (DD1)

The exact shape `bun run demo` produces to stdout:

```
clinical-reports-wrapper-poc — demo run
Template: acc-srna-skeleton    Blocks: 3    Run ID: 2026-01-01T00-00-00-000Z

[1/3] verbatim     · introduction
This report has been generated under the requirements of ACC Section 32...

[2/3] structured   · functional-status-grid    LLM call: openai/gpt-4o (canned)
| Domain        | Measure        | Value  |
|---------------|----------------|--------|
| Mobility      | Walk distance  | 50m    |
| Pain          | VAS            | 7/10   |

[3/3] generative   · clinical-impression       LLM call: openai/gpt-4o (canned)
The claimant presents with reduced functional capacity consistent with...

Done. 3 blocks · 2 LLM calls · audit/2026-01-01T00-00-00-000Z/ (2 files)
```

Rules:
- Banner line 1: `<repo-name> — demo run`.
- Banner line 2: `Template: <id>    Blocks: <count>    Run ID: <runId>` (4-space separators between fields).
- One blank line, then per-block header: `[N/total] <kind>     · <block-id>` (kind left-padded to 10 chars so `·` aligns across the run). Verbatim blocks omit the trailing `    LLM call: <model> (canned)`; structured + generative blocks include it.
- Block body follows the header line immediately, no blank line between header and body.
- One blank line between blocks.
- Final summary: `Done. <N> blocks · <M> LLM calls · audit/<runId>/ (<F> files)`. `M` excludes verbatim blocks (they make no LLM call); `F` matches `M` (one JSON file per call).

### Failure-message copy spec (DD2)

| Code path | Exact message (printed to stderr; exit non-zero unless noted) |
|---|---|
| `demo.main()` — `audit/` path is a file, not a dir | `Error: cannot create audit directory — 'audit/' is a file. Remove or rename it and re-run.` |
| `replayLLM()` — fixture file missing | `Error: fixture for block '<block-id>' not found at fixtures/llm-responses/<block-id>.json. Re-clone the repo or run 'bun run check --update' to regenerate.` |
| `replayLLM()` — fixture malformed JSON | `Error: fixture at fixtures/llm-responses/<block-id>.json is not valid JSON. Restore from git: 'git checkout fixtures/llm-responses/<block-id>.json'.` |
| `replayLLM()` — fixture missing required field | `Error: fixture '<block-id>' is missing required field '<field>'. Expected shape: { prompt, response, model, tokensIn, tokensOut, finishReason }.` |
| `audit.onFinish` — writer.write() throws (caught, demo continues, exit still 0) | `[audit:warn] failed to persist row for block '<block-id>': <error.message>. Demo continues; audit row dropped.` |

Rules:
- Hard failures: `Error: ` prefix (capitalized), lowercase next word, full stop after fix-suggestion sentence. No stack trace shown to user.
- Continued-execution warnings: `[audit:warn] ` prefix, lowercase first word, demo exits 0 (CLAUDE.md hard rule #2: audit failure must NEVER break the user-facing call).
- Always name the `block_id` or file path. Always suggest a fix where one exists.
- Implementer may log full stack traces to a `.debug.log` file if useful, but never to the user-facing stderr stream.

## What this proves

Three things, by demonstration not assertion:

1. **The agent's job is routing, not generation.** `src/router.ts` is a
   `switch (block.kind)`. The switch is the thesis: dispatch, not derive.
2. **Formatting is deterministic tool code.** `verbatim` returns fixed text.
   `structured` parses LLM JSON into a known table. `generative` wraps a
   LLM string. Three formatters, one signature, no improvisation.
3. **Every LLM call leaves a row.** The audit hook fires on every
   structured + generative call. Open `audit/<runId>/<callId>.json`
   to see prompt, response, model, tokens — pretty-printed.

## Architecture

## Why canned responses?

This is a proof of an architectural thesis, not a product. Canned LLM
responses make the demo:

- **Zero-friction.** No API key, no rate limits, no flake.
- **Deterministic.** Two runs produce byte-identical output (modulo
  run-id). The same property a real CI gate needs — see `bun run check`.
- **Scope-disciplined.** A live-API mode is one flag away (`--live`,
  v1.5) but is not the point. The architecture is fully visible in
  canned mode.

The audit row still has real shape: prompt, model, tokens, finish reason.
Nothing is faked — only the response body is replayed from
`fixtures/llm-responses/<block-id>.json`.

### Audit row shape v1 (DD4) + filename (DD5)

Single canonical shape. Supersedes the field-list at the eng-review test plan's "Audit-dir discoverability" line and the filename pattern at plan body line 38.

```json
{
  "schema_version": 1,
  "id": "call-001",
  "ts": "2026-01-01T00:00:00.000Z",
  "block_id": "functional-status-grid",
  "block_kind": "structured",
  "model": "openai/gpt-4o",
  "prompt": "Given the transcript below, extract the functional status grid as JSON…",
  "response": "{\"mobility\":{\"walk_distance_m\":50},\"pain\":{\"vas\":7}}",
  "tokens_in": 142,
  "tokens_out": 88,
  "latency_ms": 1240,
  "finish_reason": "stop"
}
```

Type changes from existing wrapper's `LlmCallRow` (at `clinical-reports-wrapper/lib/wrapper/audit.ts:22-51`):
- **Drop** `report_id`, `trace_id` — single-report PoC, no distributed tracing.
- **Rename** `sanitized_text` → `response` — no PII context in PoC; the full canned response IS the audit row body.
- **Add** `schema_version: 1` — golden-diff safety. Any v2 shape change must bump this so `bun run check` fails loudly instead of silently passing on a shape drift.
- **Add** `block_kind: 'structured' | 'generative'` — verbatim blocks emit no audit row (no LLM call), so `block_kind` in any audit file is always one of those two.
- **Reorder** so payload (prompt + response) sits mid-row. Top-to-bottom scan reads: `version → id → time → who (block_id, block_kind, model) → what (prompt, response) → cost (tokens) → outcome (latency, finish_reason)`. Founder opens the file and the thesis is visible in the first six fields.

Filename pattern (DD5):
- Path: `audit/<runId>/<callId>.json`
- `runId` = ISO timestamp with `:` and `.` replaced with `-`, e.g. `2026-01-01T00-00-00-000Z`. Deterministic under A2's fixed-clock injection (demo mode); wall-clock under live mode.
- `callId` = `call-NNN` zero-padded monotonic counter from A2's `makeId` injection. Resets per demo invocation (each run starts at `call-001`).
- `bun run check` strips the `<runId>/` dir before diffing against committed `golden/audit/`.
